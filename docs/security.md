# 安全清单与故障排查

## 上线前清单

- [ ] 白名单目录单独新建，里面没有密钥、证件、浏览器配置
- [ ] `.env` 只有本机可读（Mac/Linux `chmod 600 .env`；Windows 确认只有本人账号可读）
- [ ] `.env`、Token、隧道带 Token 的完整 URL 没有进任何仓库或聊天
- [ ] 网关带 Token 才开隧道；顺序反了先关隧道
- [ ] 删除/付款/对外发送类工具已设为人工确认，或干脆不开
- [ ] 知道怎么断开：关网关进程的窗口在哪

## 日常习惯

- 用完关网关，不要长期常驻；确需常驻时用系统服务并写清恢复方式
- 定期换 Token：重新生成、改本机 `.env`、云端连接器同步更新
- 临时隧道地址不要发到公开渠道

## 故障排查

| 现象 | 排查顺序 |
|---|---|
| Inspector 看不到工具 | Node 版本 → npx 可用 → MCP 包名拼写 → 白名单路径存在 |
| 本机 curl 网关无响应 | 网关进程是否还在 → 端口是否被占用 → `.env` 是否缺 Token/SHARE_DIR |
| 公网打不开隧道地址 | 隧道进程是否还在 → 临时地址是否已过期换新 → 本机防火墙 |
| 云端 401 | 两端 Token 是否同一枚（只报一致/不一致，不贴原文比对） |
| 云端超时 | 先在本机 curl 网关，再测公网隧道，分段定位，不要反复重连 |
| 桌面工具报错 | 是否有图形会话 → agent-desktop 是否装在本机 → 系统辅助功能/自动化权限是否已给（Mac 在系统设置里给终端/网关进程授权） |

## 权限提示（Mac）

桌面操控类工具在 macOS 上需要“辅助功能”和“屏幕录制”权限，系统设置 → 隐私与安全性里给实际运行网关的终端 App 授权，授权后重启网关进程。
